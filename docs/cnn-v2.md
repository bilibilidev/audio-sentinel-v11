# CNN v2：模型、App 与系统构建

App 默认事件分类入口已切换为因果 CNN。部署模型位于 `model/cnn-v2/`，导出头文件位于 `app/audiodetect/cnn_*v2.h`；模型 SHA256、配置和来源必须与生成记录对应。原 v11 MLP 和 CNN v1 保留用于回退及对照。

当前为待验收候选 `clean_anchor`，不是系统验证完成的正式发布。Python INT8 外部 52/65、婴儿 13/20；比 v1 只多识别一条婴儿录音，总体正确数相同。在 0.80 阈值下两版均有 7/20 条婴儿达到告警分数，尚无告警提升证据。最终候选的 Ubuntu C、系统镜像和真板运行待验收。

## 训练与对照

只使用固定的 390 条 ESC-50 五类子集训练，保留官方五折和源录音分组。不是完整 ESC-50 的 50 类成绩。归一化和分类器只拟合训练折；内层验证选择配置/epoch 后，外层保留折仅用于计分。逐个固定变体的结果与逐折选型的嵌套 CV 分开报告。

标准对照为 MFCC+SVM、MFCC+RF、PANNs Cnn6 冻结特征+线性 SVM。PANNs 用过额外 AudioSet 预训练数据，属于单独的迁移对照，不能声称训练数据预算一致或已排除预训练重叠。未运行 YAMNet、AST 或云 API，不上传音频。

预先定义的消融包括 time-only、MFCC-only、混合特征、无增强、无电话音质增强、16/24/32 通道、三组 dilation 和均值聚合。训练命令和协议见 [training/cnn_v2](../training/cnn_v2/README.md)，实际逐折结果位于 `results/cnn-v2/`。

第一轮选定模型的外部最终成绩为 45/65、婴儿 11/20，低于 v1 的 52/65、12/20，因此未作为改进版接受。第二轮改为防混叠的 8 kHz 带宽视图、固定 80 epochs，并以干净与合成电话带宽的内层验证共同选型。实际外部录音仍不参与训练或内层选型；保留失败候选及完整实验记录。

第二轮最终候选为 41/65、婴儿 11/20，仍未通过改进验收。第三轮保留 v1 初始化与均值聚合，采用小学习率微调和干净训练输入上的教师约束；各轮结果分开保存，不能只展示成功候选而隐藏退化。

随后使用外部开发集在固定微调候选中选择 `clean_anchor`，结果必须标为开发选型而非外部盲测。其固定配方 ESC-50 五折为 316/390（81.0%）；不是嵌套选型结果。额外 PANNs 特征蒸馏及宽通道教师约束试验未同时优于 v1，总体退化，未用作默认模型。当前默认候选没有引入 AudioSet 先验。

标准 baseline 的固定 390 条五类任务保留折：MFCC+SVM 312/390，MFCC+RF 293/390，PANNs Cnn6 冻结特征+SVM 367/390；对应外部最终模型分别为 39/65、40/65、58/65，婴儿分别为 12/20、12/20、16/20。PANNs 额外预训练、输入前端与轻量模型不同，不能据此声称同等数据预算。完整逐条结果随代码保存。

外部 65 条录音（含 20 条婴儿哭声）均已由用户确认标签，未加入训练。这组录音此前用于开发验证，不是全新盲测；五个 ESC-50 折模型评测同一组外部录音，不等于在外部集上重新做五折训练。最终模型使用全部 390 条训练，应与旧最终模型比较。婴儿召回之外还需核对误报和其他类别退化。

## Linux C 与 App

```sh
sh scripts/build_cnn_v2_app.sh
out/cnn-v2/audiodetect input16k.wav --debug
sh scripts/build_cnn_v2_stream.sh
out/cnn-v2/cnn_stream --live input16k.wav
out/cnn-v2/cnn_stream --stdin-raw < input16k.pcm
```

输入为 PCM16 单声道 16 kHz。WAV CLI 按 160 样本读取并保留整个文件的状态，不截为一秒。流式核心跨回调保留预加重、FFT 帧与卷积历史，每 100 ms 输出一次 EMA 分值。EOF 全片分数使用模型固定的聚合方式；不能把全片准确率当作在线 EMA 告警率。

权重和偏置采用 INT8 存储，卷积和特征仍为浮点，稳定聚合使用 double。`--int8` 是兼容参数。CLI 和 LVGL 调用共用同一实现；旧 MLP 的静音强制改判和窗口投票不再参与默认 CNN 路径，告警置信度保留 0.80。

UI 继续使用三秒 `arecord` 文件采集，每个文件内部连续推理、文件间重置状态。尚未实现无间断 PCM/I2S 输入、事件起止标注或实时报警的独立准确率验收。关键词仍为合成模板的命令行原型，不能将合成测试写为真实语音准确率。

## 系统与开发板边界

Linux C 运行、goldfish/NuttX/LVGL 对象交叉编译、完整系统镜像构建和真实开发板运行分别保存证据。对象编译通过不代表系统模拟器已运行，也不代表开发板已验收。

R528S3 Gemini S1 使用仓库冻结的 ILI9341（320×240）配置；goldfish 使用其独立配置，不能互相覆盖。真板镜像在现有 SDK 的独立副本内构建，保存实际 `repo manifest -r`、应用提交、依赖差异、工具链版本、命令和 SHA256。构建和打包不会自动烧录；真实麦克风、屏幕、触摸、延迟和稳定性由后续真板测试确认。未锁定原历史依赖，不声称新镜像与历史镜像字节一致。

`scripts/build_r528s3_cnn_image.sh` 只对带隔离标记、应用提交一致且有实际最终 C 验收记录的 SDK 构建和打包。它不安装依赖、不烧录；会检查最终模型 SHA 出现在 AP 固件中，并核验新生成的 Allwinner IMAGEWTY 容器，不能仅凭厂商脚本退出码宣称打包成功。当前仅完成旧应用的系统依赖预构建，完整 v2 可烧录包尚未生成。
