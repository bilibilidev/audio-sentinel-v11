# R528S3 真板与模型资源对照（2026-10-20）

当前 CNN v2 在用户分区擦除烧录后的 Gemini S1 真板完成 65 条完整 WAV 测试：**52/65（80.0%）**，与 Linux C 的 65 条预测全部一致。板端固定三秒 WAV 推理均值 **223.3 ms**、P95 **224 ms**。模型、特征和告警门限未改，也未重新训练 CNN。

这些是板端文件输入成绩。65 条均经用户听审，来自 ESC-50 之外，但已参与模型开发选型，不能写成独立盲测、实际麦克风准确率或现场告警效果。样本量较小，不能外推到所有真实场景。

## 板端时延、内存与状态

| 项目 | 实测结果 | 口径 |
|---|---:|---|
| 固定三秒 WAV | 均值 223.3 ms；P50 223 ms；P95 224 ms | 预热 3 次后 20 次；另一轮发布脚本复测均值/P95 相同 |
| 65 条变长 WAV | 均值 620.45 ms；P50 511 ms；P95 1452.8 ms | 长短录音不可直接当作固定窗口时延 |
| 65 条总音频/总处理 | 538.880 s / 40.329 s | 总处理/总音频 = 0.07484；逐条 RTF 均值 0.07494 |
| Python/Linux C 对照 | 65/65 预测一致；最大概率绝对差 6.14e-6 | 输入往返 SHA256、完整样本数均通过 |
| CNN 流式状态 | 21,048 B（20.55 KiB） | ARM ABI 的 sizeof；不含只读权重、DSP 表、临时栈、OS、UI |
| UI 存活且停止采集时堆 | total 100,809,076 B；after free 98,618,368 B | 系统堆，不能写成模型独占 RAM；快照与高水位见 JSON |
| 完整固件静态段 | text 5,234,080 B；data 72,536 B；bss 7,007,624 B | 完整 OS + 驱动 + App，不是 CNN 单模型 |

NSH `time` 包含文件 IO、DSP、CNN、stdout，并受正常任务调度影响；界面保持存活，测固定 WAV 时采集已暂停。不含 USB 传输和录音，也不是事件发生到屏幕告警的端到端延迟。NSH 输出约 1 ms 分辨率，P95 为样本线性插值；20 次不构成长时间稳定性保证。CLI 以 160 样本连续喂入、保留整个文件的状态，在线 EMA 的 100 ms 输出节拍不等于端到端告警时延。

**采集稳定性未通过本次完整验收**：用户按 STOP、界面 IDLE 后，同一 arecord 进程仍在等待，录音文件仅 30,720 帧，未达到三秒应有的 48,000 帧。结束残留采集后，直接短命令录音返回但未产生新 WAV。因此本次没有有效的“三秒录音+推理”时延，也没有真实麦克风准确率；不能把异常返回的 2 ms 当成采集速度。原始诊断证据见 [停止残留采集](logs/stop-residual-capture.log)、[直接采集检查](microphone-direct.json)、[无 time 包装复核](microphone-unwrapped.json)。本轮仅清理残留进程，未修改系统或重新烧录。

## 轻量化与主机性能

下列性能在同一台 Intel i7-14650HX 的 Windows 主机上用 CPU 单线程 PyTorch、batch=1 测量，两模型分别启动新进程，均预热 3 次、测 10 次。输入是同一条录音的 3/5/10 秒前缀，PCM SHA 完全相同；各模型使用自身规定的前端。不能将主机结果套用到 ARM 真板，也不能拿 PyTorch RSS 当原生 C 内存。

| 项目 | CNN v2 | PANNs Cnn6 + SVM |
|---|---:|---:|
| 可学习网络参数 | 14,885 | 4,837,455（另有 SVM 2,565 参数） |
| 网络可学习权重存储 | INT8 14,885 B + 48 B 尺度 | FP32 19,349,820 B；另有固定前端、BN 状态和 SVM |
| 分发模型文件 | NPZ 81,015 B（含导出信息等） | 官方 checkpoint 23,698,321 B；不含 SVM |
| 5 秒网络 Conv/Linear MAC | 7,350,480 | 4,953,927,168；另有固定 STFT Conv 526,362,624 与 SVM 2,560 |
| 主机 3 秒 PCM 前端+推理均值 | 1.938 ms | 363.013 ms |
| 主机 5 秒 PCM 前端+推理均值 | 3.449 ms | 596.208 ms |
| 主机 5 秒 PCM 前端+推理 P95 | 3.683 ms | 615.943 ms |
| 主机 10 秒 PCM 前端+推理均值 | 8.436 ms | 1,224.212 ms |
| 新进程工作集峰值 | 232,038,400 B | 455,712,768 B |
| 当前真板时延 / RAM | 上表为实际原生 C 测量 | 未部署，未测 |
| 板端功率 / 单次能耗 | 未测 | 未测 |

CNN 网络参数约少 **325 倍**，5 秒网络卷积/线性 MAC 约少 **674 倍**，本次主机含前端平均耗时约少 **173 倍**。这支持“更轻量、当前硬件上有较低计算开销”的结论，不能写为更准确或已实测更省电。模型存储精度不同，CNN 是 INT8 存储但浮点卷积，并非全 INT8 运算。MAC 不是全算法 FLOPs：不计 BN、非线性、池化、非 Conv/Linear 的 FFT/Mel、内存搬运；PANNs 保留本次 baseline 使用的完整前向（含 AudioSet 头）。CNN 的前端表不包含在 14,933 B 学习权重与尺度中。工作集含 Python、PyTorch、库和缓存，仅代表主机进程。

**功耗：用户确认没有功率计，W 和 J 均为 null。** 不能从参数/MAC/时延直接宣称节电百分比。后续要测板级空闲、采集、固定 WAV 推理和完整循环功率，应保持供电、LCD 亮度、WiFi、采样设置和线程一致，记录仪器采样率，积分每次任务的功率并注明是否扣空闲基线。PANNs 先在同一硬件成功部署后才有同板功耗对照；当前不估算 PANNs 在板端的 W、J 或时延。
