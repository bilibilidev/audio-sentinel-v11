# Tiny MLP：真实 R528S3 开发板实验（2026-10-27）

正式模型保持不变：92→96→5、9,413 参数，SHA256 `2c74151ca171eff88af7efa26b8a4b3dfc37ea42c7e77b0c9b379bd61610f9e9`。实际执行为 Gemini S1 / OpenVela-NuttX / 板载 ILI9341。**核心 WAV 推理已验证，整机验收未通过：批量 NAND 写入出现 SPI0 超时与 YAFFS 重试。**

本轮使用已听审、已用于开发选型的外部 65 条（FSD50K 45 条 + Donate-a-Cry 婴儿 20 条）。它们没有用于梯度训练，但不是新盲测；WAV 分类不等于现场麦克风准确率。本轮未重训或替换权重，也未在板端安装五折模型；337/390 五折仍属于 [Linux C 固定配方实验](../mlp-study-20261026/README.md)。

## 内存、存储与系统状态

- 冷启动记录为 `power_on(0)`，固件编译日期为 10 月 27 日，测试前已观察到 UI 自启进程。用户确认小屏正常、STOP 后 IDLE；未额外执行重启循环或自动化触摸精度测试。
- 释放本轮专用 RAM 临时输入后，系统堆使用 2,130,228 B，空闲 98,711,640 B；这是 **OS/UI/ADB 等全系统堆，不是模型独占峰值**。`maxused=72,581,888 B` 被约 69 MB 的临时测试 WAV 占用污染，不能作为 MLP 峰值 RAM。短时循环 10 个空闲采样的 used 范围为 72,478,444–72,479,036 B，不能据此宣称长期无泄漏。
- UI 主线程报告 StackUsed/StackSize 为 5,068/65,480 B，工作线程为 5,176/65,512 B；仅是对应存活线程的 NuttX 栈记录，不是每次 CLI 推理峰值。
- 初次向 NAND 批量传入约 51 MB 后，SPI0 出现 `xfer timeout`，YAFFS 出现 `chunk ... was not erased` 及 `write required 95 attempts`。ADB 随后恢复，uptime 和复位原因表明系统没有重启。**没有认定唯一根因，也没有据此认定是电源或模型内存冲突。**后续不再新增 NAND 写入，改用现有 `/tmp` tmpfs；已存 NAND clean65 在故障后重新只读回传，哈希通过才评分。
- RAM 输入共 280 个文件均往返校验。五次本地麦克风录音仅留本地；结束后只释放本轮创建的 RAM 临时文件，保留 NAND 测试文件及旧环境、模型和镜像。没有读取整块 NAND、格式化、重刷或改模型。
- 没有功率计，功率/能耗未测；PANNs 没有同板部署。带标签的声学现场准确率、实际告警时延、每小时误报、NAND/UI 长期录音及 1h/24h 稳定性均未验收。

故障证据：[传输恢复与内核日志](transfer-recovery.json)、[最终内存/栈/时钟](final-inspection.json)、[状态总表](summary.json)。失败尝试另存于 `failed-attempts/`，没有把失败的链路测试改写成成功。
